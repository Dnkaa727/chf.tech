# Диагностика ошибки оценки v3

Эта сборка добавляет диагностику; причина сбоя конкретного реального GPT-запроса
пока не установлена. Правила оценивания, цитирования и Rubrics не ослаблены.

При HTTP 502 тело ответа остаётся прежним:

```json
{"detail":"LLM evaluation failed. Retry or request human review."}
```

В Swagger откройте **Response headers**:

- `x-llm-error-code` — категория причины;
- `x-request-id` — идентификатор для поиска события в серверном логе;
- `x-llm-provider-status` — HTTP-код провайдера, если получена HTTP-ошибка.

| Код | Что проверять |
|---|---|
| `invalid_configuration` | Переменные окружения и выбранные режимы |
| `provider_http_error` | Код `x-llm-provider-status`: доступ, квоты, поддержка запроса |
| `provider_timeout` | Время ответа Hubris и настройку таймаута |
| `provider_unavailable` | Сетевое соединение или прерванный HTTP-ответ |
| `invalid_json` | Провайдер вернул невалидный JSON |
| `unexpected_response` | Структуру Chat Completions / тип `message.content` |
| `incomplete_response` | Генерация не завершилась обычным текстовым ответом |
| `schema_mismatch` | Обязательные поля, типы, enum и лишние поля JSON |
| `invalid_quote` | GPT вернул неподтверждённую дословную цитату |
| `invalid_error_link` | Привязку к критериям или существующим `error_id` |
| `schema_definition_error` | Схема содержит неподдерживаемые локальным валидатором правила |
| `unexpected_error` | Нужна дополнительная диагностика кода сервера |

Сервер пишет событие `llm_evaluation_failed` в logger `rag.v3.llm` с уровнем WARNING.
Событие содержит только ID запроса, код, ID карточки, известный ID критерия,
разрешённое имя поля и HTTP-статус провайдера. Исходные тексты исключений, ответ
кандидата, тело ответа провайдера, промпты, URL и ключи не записываются.

Например, `schema_mismatch` и `field=resolutions` означают проблему поля
`resolutions`, а не плохие знания кандидата. `invalid_quote` может дополнительно
указать `criterion_id` в серверном логе; в публичный ответ этот ID не добавляется.

После обновления сервер нужно перезапустить. ML-инженер может повторить один
проблемный запрос в пределах согласованного GPT-бюджета и передать код причины,
request ID и безопасную строку лога. Реальные GPT-запросы при подготовке сборки
не выполнялись. Изменять ответ кандидата ради прохождения проверки не требуется.
