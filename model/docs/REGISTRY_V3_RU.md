# Каталог, рубрики и выбор карточки v3

`data/knowledge_base.json` (schema 2.0) содержит каталог: ID, компетенцию, тему,
уровень, стартовый вопрос, поисковые признаки и происхождение требований.
Критериев оценивания и уточнений в этом файле нет.

`data/rubrics_all_25.json` — единственный актуальный источник пяти критериев
0/1/2 для каждой карточки, red flags и уточнений. Все 125 критериев сохранены.
Повторённые в рубриках тема, вопрос и уровень проверяются на точное совпадение
с каталогом; они не образуют независимую версию каталога.

`v3.registry.CardRegistry` соединяет данные через `cards[].id == rubrics[].card_id`.
До построения индекса проверяются дубли ID, затем соответствие всех 25 пар,
метаданные, критерии, якоря, версии, уточнения и определения флагов. В актуальный
каталог запрещено добавлять поля оценивания.

## API для будущего React-клиента

1. `GET /v3/cards` — публичный каталог и `registry_version`.
2. `POST /v3/cards/select` — серверный выбор карточки. Например:

   ```json
   {"query":"индексы PostgreSQL"}
   ```

   Можно передать `competency` как фильтр по названию/алиасу либо явный `card_id`.
   Успех: `card`, `rubric_version`, `registry_version`.

   При нескольких подходящих карточках: HTTP 409, `detail.code=ambiguous_card`,
   `detail.candidates` — публичные варианты. Приоритет демо и порядок ID не
   используются для автоматического разрешения неоднозначности. Неподходящий
   запрос даёт 404; пустой — 422. Сам выбор не создаёт сессию и не вызывает GPT.

3. `POST /v3/session/start` с выбранным ID:

   ```json
   {"card_id":"PG-QUERY-01"}
   ```

4. `POST /v3/session/answer` с `session_id` и `candidate_answer`.
5. `GET /v3/session/{session_id}` — прежний контракт состояния темы.

Публичные карточки формируются по списку разрешённых полей и отдельным моделям
ответов FastAPI. Они содержат стартовый вопрос и ссылки на источники, но не
критерии, якоря, определения флагов, уточнения и промпты.

`/v3/rubrics` по-прежнему выдаёт только метаданные. `/v3/prepare` сохраняется как
внутренний интерфейс ML-интеграции: он содержит скрытые рубрики и не должен
проксироваться кандидатскому React-клиенту. Пометка internal не является
авторизацией; существующая модель доступа этим изменением не заменяется.

## Снимки и обновление данных

Реестр загружается и проверяется один раз на процесс; production startup FastAPI
проверяет его до приёма запросов. Для нового выпуска данных нужен перезапуск
процесса или явная внутренняя очистка кеша `get_registry.cache_clear()`.
Автоматической перезагрузки файлов на каждом запросе нет.

Тематическая сессия получает собственную копию карточки и рубрики, фиксирует
`rubric_version`, `rubric_hash` и `registry_version`. Промпт, JSON Schema,
проверка ответа и уточнения используют этот снимок. Изменение файла или обновление
реестра не меняет существующую сессию. Версия для сессии определяется при её старте.

## Совместимость

Маршруты `/v1/*` и `/v2/*` сохранены и помечены deprecated/legacy в OpenAPI.
Они используют `data/legacy/knowledge_base_v1.json` — побайтную копию прежней KB
с 75 историческими критериями. Новый v3 не загружает этот снимок.

`data/knowledge_cards.json` оставлен: его используют старый поиск `src/core.py`
и эксперимент `extras/pgvector/vector_store.py`. `rubric_postgresql.json` нужен
v2. Эти файлы не являются источниками оценивания v3.

React ещё не реализован. Остаётся подключить публичный выбор, показать кандидату
варианты при 409, отправлять ответы в существующую сессию и организовать защищённый
backend/proxy. Сессии по-прежнему хранятся в памяти процесса.
