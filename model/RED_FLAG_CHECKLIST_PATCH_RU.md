# Патч: обязательная проверка red flags на Stage 2

## Что меняется

1. Stage 2 больше не возвращает готовый массив `red_flags`.
2. Вместо него модель обязана вернуть объект `red_flag_checks` со всеми ID из `red_flag_definitions` текущей рубрики.
3. Для каждого определения возвращаются `detected`, `evidence_ids` и `reason`.
4. Python проверяет полноту чек-листа, допустимость ID и наличие конкретного evidence для каждого сработавшего флага.
5. Python строит привычный массив `red_flags` в порядке определений рубрики. Публичный формат оценки и формат `red_flags` не меняются.
6. `error_updates` от Stage 2 теперь указывают `flag_id`; Python преобразует его в прежний внутренний `flag_index`, поэтому состояние сессии остаётся совместимым.

## Установка

Скопируйте `v3/engine.py` в проект поверх существующего файла `v3/engine.py`.
Скопируйте `tests/test_v3_red_flag_checklist.py` в папку `tests/`.

Запустите из корня проекта:

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_v3_red_flag_checklist.py -q
```

## Проверка двух диагностических сценариев

- Противоречия `time.sleep` должны дать `technical_contradiction` с конкретными ID сегментов.
- Категоричное утверждение, что event loop никогда не блокируется, и вывод «успешный запуск доказывает отсутствие блокировок» должны оцениваться по существующему определению `confidently_incorrect`.

В рубриках сейчас нет отдельного `unsupported_claims`. Патч не добавляет новую категорию и не меняет 25 файлов рубрик или `SIGNIFICANT_ERROR_FLAGS`.

## Важно

Количество запросов к LLM не увеличивается: остаются те же два этапа. Но Stage 2 теперь получает обязательную проверку каждого определения флага. Это повышает полноту проверки, но не превращает семантическое решение модели в абсолютную гарантию; диагностические тесты и экспертная проверка по-прежнему нужны.
