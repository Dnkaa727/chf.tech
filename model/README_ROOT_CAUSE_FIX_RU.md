# Патч первопричин двух ошибок Stage 1 / Stage 2

## Что показали логи и исходный код

### `invalid_quote` на этапе `segmentation`

В старом Stage 1 LLM самостоятельно формировала `quote`. Затем `validate_segments()` пыталась найти эту строку в ответе кандидата. Нормализация учитывала Unicode NFKC, регистр, пунктуацию и пробелы, но не могла исправить перефразирование, пропуск слов, изменение окончания или объединение отдельных частей. В таком случае точная подстрока отсутствовала и оценка завершалась `invalid_quote`.

### `schema_mismatch` на этапе `scoring` для K5

Старый Stage 2 возвращал массив `segment_assessments`. JSON Schema разрешала элементам использовать `segment_ids` всего ответа, когда у критерия не было маршрутизированных фрагментов (`allowed_ids or segment_ids`). При этом Python требовал точного совпадения с набором ID, назначенных конкретному критерию. Для пустого критерия модель могла вернуть глобальный ID, который формально проходил схему, но затем приводил к `schema_mismatch`. Для непустого критерия схема также не обеспечивала полноту массива и уникальность ID; это проверялось только постфактум.

Лог не показывает, какой именно из вариантов произошёл у K5 (лишний ID, пропущенный ID или дубликат), но исходный контракт действительно допускал такие рассогласования.

## Исправления

1. **Stage 1: Python создаёт фрагменты.** Ответ разбивается по границам предложений, точкам с запятой и переносам строк. Python задаёт `S001...` и сохраняет точные исходные диапазоны. LLM больше не возвращает `quote`: она только задаёт `claim_type` и `criterion_links` для каждого обязательного ID. Python восстанавливает цитату напрямую из исходного текста.
2. **Stage 2: фиксированный объект вместо массива.** `segment_assessments` теперь объект, где ключи — точные ID фрагментов, связанных с критерием. JSON Schema требует каждый ключ ровно один раз и запрещает посторонние ключи. Для критерия без связанных фрагментов используется явный маркер `{"__no_evidence__":"not_applicable"}` — пустой объект не требуется.
3. **Диагностика.** Ошибки локальной проверки ответа от провайдера сохраняют `stage`, чтобы `schema_mismatch` до `check_segmented_output()` не терял этап происхождения.
4. Сохранена совместимость функций валидации с прежними массивами/цитатами для старых offline-тестовых фикстур. Live-пайплайн использует только новый ID-протокол.

## Что не меняется

- публичный JSON-ответ `/v3/evaluate`;
- пять критериев, их anchors и диапазон 0–10;
- правила Red Flags и error/resolution state;
- одностадийный режим `/v3` (`LLM_PIPELINE_MODE=one_stage`);
- количество LLM-вызовов: остаётся два в `two_stage`;
- повторные вызовы не добавлены.

## Ограничение разбиения текста

Python использует консервативные границы: конец предложения, `;`, перевод строки. Это гарантирует точные цитаты, но если кандидат написал несколько независимых мыслей в одном длинном предложении без этих разделителей, они останутся одним фрагментом. Такой фрагмент может быть привязан к нескольким критериям; Stage 2 оценивает его отдельно для каждого. Это сознательный компромисс в пользу точного источника и отсутствия выдуманных цитат.

Из корня `D:\RAG_BACKEND_ALL_25`:

```powershell
$stamp = Get-Date -Format "yyyyMMdd-HHmmss"
Copy-Item .\v3\engine.py ".\v3\engine.py.$stamp.bak"
Copy-Item .\v3\llm.py ".\v3\llm.py.$stamp.bak"

Expand-Archive .\RAG_BACKEND_ALL_25_ROOT_CAUSE_FIX.zip .\_root_cause_fix -Force
Copy-Item .\_root_cause_fix\v3\engine.py .\v3\engine.py -Force
Copy-Item .\_root_cause_fix\v3\llm.py .\v3\llm.py -Force
Copy-Item .\_root_cause_fix\tests\test_v3_root_cause_fix.py .\tests\ -Force
```

Запуск новых тестов:

```powershell
.\.venv\Scripts\python.exe -m pytest tests\test_v3_root_cause_fix.py -q
```

Затем полный регрессионный набор проекта:

```powershell
.\.venv\Scripts\python.exe -m pytest -q
```

Перезапусти uvicorn после замены файлов.
