# chf.tech — RAG-интервьюер

Бэкенд технического интервью: находит тему в базе знаний, передаёт её вопрос и
критерии в LLM, проверяет доказательства в ответе и выбирает уточняющий вопрос.
В базе сейчас 25 тем по Python Backend. Поиск работает по словам, тегам и
синонимам; загрузки произвольных документов и векторного поиска здесь нет.

## Где что лежит

```text
model/
  run.py              — единственная точка запуска
  app/                — HTTP API
  rag/                — поиск, реестр знаний, оценка и состояние интервью
  data/               — карточки, критерии и синтетические примеры
  tests/              — единый набор offline-тестов
```

Основные данные: `knowledge_base.json` содержит темы и вопросы,
`rubrics_all_25.json` — критерии оценки. `eval_cases_all_25.json` и
`redteam_cases_all_25.json` нужны для проверок. При изменении вопроса обновляйте
карточку и соответствующую рубрику вместе: реестр проверяет их согласованность.

## Установка и запуск

Нужен Python 3.12 или новее. Команды выполняются из корня репозитория.

```sh
python -m venv .venv
source .venv/bin/activate
python -m pip install -r model/requirements-dev.txt
python model/run.py check
python model/run.py test
python model/run.py serve
```

В Windows вместо `source` используйте `.venv\Scripts\Activate.ps1`.
Для одного запуска API без тестов достаточно `model/requirements.txt`.
Сервер слушает `127.0.0.1:8000`; интерактивное описание запросов доступно по пути
`/docs`, проверка состояния — `/health`. Порт можно изменить через `serve --port 8001`.

## Как работает RAG

1. `search` или `POST /api/cards/select` выбирает тему по запросу. Если подходят
   несколько карточек, сервис возвращает кандидатов и просит уточнить выбор.
2. Карточка задаёт вопрос, её рубрика — пять критериев и признаки ошибок.
3. LLM сначала выделяет фрагменты ответа и связывает их с критериями, затем оценивает
   их по рубрике. Python проверяет структуру результата, ссылки и привязку цитат.
4. Сессия сохраняет доказательства и задаёт максимум два уточняющих вопроса.

Посмотреть каталог и проверить логику без ключа LLM:

```sh
python model/run.py cards
python model/run.py search "asyncio"
python model/run.py mock
```

`mock` проверяет 150 синтетических примеров с заранее заданными оценками.
Успешный прогон подтверждает логику программы, но не качество оценок реальной LLM.

## Подключение LLM

Нужен провайдер с OpenAI-совместимым `/chat/completions` и JSON Schema.
Настройки передаются через переменные окружения; перечень есть в `model/.env.example`.
Сам файл `.env` автоматически не загружается. В облачной среде ключ задаётся через
защищённые настройки среды. Локально задайте `LLM_API_KEY` в окружении процесса.

```sh
export LLM_BASE_URL="https://api.openai.com/v1"
export LLM_MODEL="gpt-4o-mini"
python model/run.py evaluate PY-ASYNC-01 --answer "Мой ответ на вопрос"
python model/run.py interview PY-ASYNC-01
```

Оценка по умолчанию делает два запроса к провайдеру на ответ и может быть платной.
Без ключа работают каталог, поиск, начало сессии и offline-тесты.

## HTTP API

| Запрос | Назначение |
| --- | --- |
| `GET /api/cards` | Каталог тем без скрытых критериев |
| `POST /api/cards/select` | Поиск: `{"query":"asyncio"}` или явный `card_id` |
| `POST /api/evaluate` | Оценка: `card_id`, `candidate_answer` |
| `POST /api/session/start` | Начало интервью: `card_id` |
| `POST /api/session/answer` | Следующий ответ: `session_id`, `candidate_answer` |
| `GET /api/session/{session_id}` | Состояние интервью |

Сначала выберите карточку, затем передайте её `card_id` для оценки или сессии.
Неоднозначный поиск и одновременный ответ в занятую сессию возвращают `409`.
Ошибка провайдера возвращает `502`, а ответ можно повторить.

Это локальный прототип: авторизации и постоянного хранения сессий пока нет.
После перезапуска сессии теряются; запускайте один процесс сервера. Внутренний
`/api/prepare` раскрывает рубрику и предназначен для отладки интеграции.
Результаты требуют проверки человеком; неподтверждённые цитаты помечаются для
ручной проверки. Не используйте баллы для автоматического решения о найме.

## Проверки

`python model/run.py test` запускает весь набор через pytest, включая тесты API,
сегментации, цитат, ошибок провайдера и параллельных ответов. Тесты подменяют LLM
и не отправляют платных запросов. Для отдельного файла:

```sh
cd model
python -m pytest tests/test_session_concurrency.py -q
```
