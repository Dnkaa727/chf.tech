# chf.tech

ИИ-платформа для проведения технических собеседований в финтехе.

## Запуск через Docker

Из корня репозитория выполните:

```bash
docker build -t chf-tech .
```

Запустите контейнер, передав ключ LLM:

```bash
docker run --rm \
  --name chf-tech \
  -p 5173:5173 \
  -p 8081:8081 \
  -e LLM_API_KEY="ваш-llm-ключ" \
  chf-tech
```

Откройте приложение:

```text
http://localhost:5173
```

Проверить backend:

```text
http://localhost:8081/health
```

При необходимости можно переопределить модель и сервис, предоставляющий модель:

```bash
docker run --rm \
  -p 5173:5173 \
  -p 8081:8081 \
  -e LLM_API_KEY="ваш-llm-ключ" \
  -e LLM_BASE_URL="https://api.openai.com/v1" \
  -e LLM_MODEL="gpt-4o-mini" \
  chf-tech
```

Остановить контейнер: `Ctrl+C`.

## Запуск через NixOS

В корне репозитория выполните:

```bash
export LLM_API_KEY="ваш-llm-ключ"
nix run .#all
```

Или запустите компоненты отдельно:

```bash
export LLM_API_KEY="ваш-llm-ключ"

nix run .#backend
nix run .#frontend
```

Приложение будет доступно по адресу:

```text
http://127.0.0.1:5173
```

Backend:

```text
http://127.0.0.1:8081/health
```


## Барс-интервьюер и озвучивание

В окне интервью отображается 2D-барс в костюме. Нажмите **«Включить голос»**:
он прочитает текущую реплику, затем будет последовательно озвучивать новые
вопросы, уточнения и обратную связь. Текст остаётся в чате. **«Повторить»**
заново читает последнюю реплику; **«Выключить голос»** останавливает речь и
автоматическое озвучивание. При завершении интервью итоговый экран открывается
после последней реплики; при ручном выходе звук останавливается сразу.

Озвучивание выполняет **Silero TTS через GenAPI**. Браузер проигрывает готовое
аудио; установленный русский голос Windows больше не нужен. Ключ GenAPI
хранится только на backend в `GENAPI_API_KEY`. Это отдельный ключ от `LLM_API_KEY`
для оценки ответов. Не добавляйте его в `VITE_*`, исходники или Dockerfile.

Настройки backend:

| Переменная | Значение |
|---|---|
| `GENAPI_API_KEY` | Ваш ключ GenAPI, обязателен для озвучивания |
| `GENAPI_TTS_SPEAKER` | Необязательное переопределение голоса; без него используется голос GenAPI по умолчанию (`xenia` в документации) |
| `GENAPI_TTS_SAMPLE_RATE` | Необязательная частота: `8000`, `24000`, `48000`; без неё используется частота GenAPI по умолчанию (`8000` в документации) |

Модель: `https://api.gen-api.ru/api/v1/networks/silero-tts`.
По умолчанию отправляется минимальный запрос из примера документации:
`{"text": "реплика интервьюера", "callback_url": null}`. Остальные параметры
выбирает GenAPI: по документации это асинхронный режим, русский язык, формат
OGG, автоматические ударения и «ё», без SSML. Голос и частота добавляются в
запрос только при явно заданных переменных выше. Для частоты используется
строковое представление, как в JSON-примере провайдера. Backend опрашивает
`GET https://api.gen-api.ru/api/v1/request/get/{id}` до готовности и получает URL записи из
`output`, скачивает аудио без передачи API-ключа на файловый сервер и отдаёт
его браузеру. Сетевой доступ нужен к API и хранилищу аудио, указанному GenAPI.
Озвучиваются только существующие реплики интервьюера; ответы пользователя
этим запросом в GenAPI не отправляются.

При первой загрузке реплики может быть задержка. Повторные запросы одной
реплики объединяются; аудио кэшируется в памяти (до 32 МиБ), а ссылка на запись
сохраняется на время жизни интервью. После вытеснения аудио из кэша повтор
скачивает ту же запись без новой генерации. Перезапуск backend очищает интервью
и кэш. Ожидание задачи ограничено 90 секундами. После таймаута повтор продолжает
опрос того же `request_id`, без новой генерации. Если сеть оборвалась при отправке
и ID задачи не был получен, приложение не отправляет текст повторно автоматически:
сначала проверьте запрос в кабинете GenAPI, чтобы избежать повторной оплаты.

При ошибке в журнале backend появляется строка `GenAPI TTS failed` с этапом
(`submit`, `poll` или `download`), HTTP-кодом и ID задачи, если он получен.
При отклонении параметров (HTTP 400/422) интерфейс показывает названия полей,
которые GenAPI пометил как ошибочные. Отклонённый запрос можно повторить после
исправления параметров; при неоднозначном результате отправки исходная причина
ошибки сохраняется, и повторная платная генерация не запускается. Ключи, заголовки,
полные ответы провайдера и текст интервью в диагностический журнал не выводятся.

Для запуска в PowerShell сначала задайте настройки Hubris, затем безопасно
введите отдельный ключ GenAPI (не публикуйте его):

```powershell
$sec = Read-Host "Ключ GenAPI" -AsSecureString
$env:GENAPI_API_KEY = ([System.Net.NetworkCredential]::new("", $sec)).Password.Trim()
Remove-Variable sec

docker build -t chf-tech .
docker run --rm --name chf-tech -p 5173:5173 -p 8081:8081 `
  -e LLM_API_KEY -e LLM_BASE_URL -e LLM_MODEL -e LLM_TIMEOUT_SECONDS `
  -e LLM_PIPELINE_MODE -e LLM_JSON_MODE -e LLM_MESSAGE_MODE `
  -e GENAPI_API_KEY chf-tech
```

Перед запуском нового контейнера остановите предыдущий. Чтобы выбрать другой
поддерживаемый Silero голос, задайте `GENAPI_TTS_SPEAKER` и передайте его через
`-e GENAPI_TTS_SPEAKER`. Без ключа озвучивание покажет понятную ошибку;
интервью остаётся доступным в чате. Синтез начинается только после нажатия
**«Включить голос»**. Микрофон не нужен: ответы по-прежнему вводятся текстом.

Движения рта привязаны к событиям воспроизведения речи, а не к отдельным фонемам.
При включённом системном уменьшении анимации движения отключаются.
Для обновления интерфейса в Docker пересоберите образ и пересоздайте контейнер.
